# Tidbits: Block Styling System

## Current state (on `change/a11y-iapi`)

- A11y markup is implemented: accordion uses APG disclosure pattern
  (`<h3><button aria-expanded aria-controls>` + `<div inert aria-labelledby>`).
  Stacked/columns keep `<dl>/<dt>/<dd>`. `view.js` store, `wp_unique_id()` IDs,
  `:focus-visible`, `prefers-reduced-motion` — all in place.
- `class-styles.php` exists: a 22-token registry + `get_global_css()` + an
  `enqueue_block_assets` hook. **This is being removed** (see item 3 below).
- `style.scss` consumes tokens via `var(--tidbits-*)` on leaf elements at normal
  specificity. **This needs refactoring** (see item 2 below).
- Parent `block.json` supports: `html`, `anchor`, `align`, `layout`,
  `spacing` (margin/padding). **No `color`, `typography`, `border` yet.**
- Morsel `block.json` supports: `html`, `reusable`. **Stays support-less.**

---

## Goal

A three-layer styling cascade, with each layer overriding the previous:

```
token defaults  →  [theme.json + Global Styles]  →  per-block instance
  (zero spec)           (WordPress-generated)           (inline styles)
```

- **Token defaults** — the floor. Plugin-owned CSS custom properties for all
  visual knobs, emitted at zero specificity via `:where()` so they're true
  defaults of last resort.
- **theme.json + Global Styles** — one merged layer. A theme can set block
  styles in `theme.json`; a site admin can override those in the Site Editor.
  WordPress generates the CSS from this merge automatically.
- **Per-block instance** — inline `style=""` attributes generated by block
  supports, overriding the global layer for that one block.

Block supports (via `selectors`) route each property to the correct inner
element, not just the wrapper. This is what makes Global Styles and per-block
controls actually work for a block with complex inner structure.

---

## Locked decisions

1. **`color.background` target** → the whole block wrapper (`.tidbits`).
2. **`border` target** → per-morsel divider box (`.tidbits-morsel`).
3. **Token defaults source** → CSS only (`:where()` in `style.scss`).
   `class-styles.php` is removed.
4. **Typography scope:**
   - **Header** (trigger + static term): `fontSize`, `fontFamily`, `fontWeight`.
   - **Content** (panel inner): `fontSize` only. Content font-size also
     normalizes heading blocks inside the panel (see below). `fontFamily` and
     `fontWeight` are token-only for content — consistent body text is the
     right default.
5. **Morsel** stays support-less. Site Editor shows one clean "Tidbits" entry.
6. **Heading normalization inside content panels** — headings inside
   `.tidbits-morsel__inner` inherit the content font-size token. Implemented
   as a zero-specificity reset so deliberate theme overrides still win.
   Rationale: Tidbits are UI components (bite-sized content), not documents.
   A stray `h2` bursting out of a collapsed panel is an accident, not intent.

### 2. `src/blocks/tidbits/style.scss`

**Refactor token-default leaf rules to zero specificity using `:where()`.**

Any rule that sets a property which block supports will also set must be at
zero specificity so Global Styles and per-block values automatically win.

Pattern:

```scss
// Before (0,1,0 — blocks Global Styles):
.tidbits-morsel__trigger {
  font-size: var(--tidbits-term-font-size);
}

// After (0,0,0 — true default of last resort):
:where(.tidbits-morsel__trigger) {
  font-size: var(--tidbits-term-font-size);
}
```

Rules to wrap in `:where()`:
- `.tidbits-morsel__trigger` (all font/color/background properties)
- `.tidbits .tidbits-morsel__term` → `:where(.tidbits) :where(.tidbits-morsel__term)`
- `.tidbits-morsel__content` and `.tidbits-morsel__inner` (color, font-size)
- `.tidbits-morsel` (border declarations)
- `.tidbits-morsel__panel` (background)

Rules that do NOT need `:where()` — structural layout, not support-exposed:
- Display, grid, overflow, transitions, transforms, cursor, width, gap, etc.
- Focus-visible ring (intentionally higher specificity than the default)
- `.tidbits .tidbits-morsel__heading` reset (must beat theme `h3` rules —
  keep at `0,2,0`)
- Reduced-motion `@media` block

**Add heading normalization inside content panels:**

```scss
:where(.tidbits-morsel__inner) :where(h1, h2, h3, h4, h5, h6) {
  font-size: var(--tidbits-content-font-size);
}
```

Zero specificity on both parts — a deliberate theme or block style still wins.

**Move token default values into CSS** (replacing the PHP class):

```scss
:where(.tidbits) {
  --tidbits-term-font-family: inherit;
  --tidbits-term-font-size: 1rem;
  --tidbits-term-font-weight: 600;
  --tidbits-term-line-height: 1.4;
  --tidbits-term-color: inherit;
  --tidbits-term-color-hover: inherit;
  --tidbits-header-bg: transparent;
  --tidbits-panel-bg: transparent;
  --tidbits-content-color: inherit;
  --tidbits-content-font-size: inherit;
  --tidbits-focus-color: currentcolor;
  --tidbits-padding-block: 0.75rem;
  --tidbits-divider-color: #e5e5e5;
  --tidbits-divider-width: 1px;
  --tidbits-divider-style: solid;
  --tidbits-panel-inset: 0;
  --tidbits-columns-term-width: 260px;
  --tidbits-columns-gap: 1.5rem;
  --tidbits-trigger-gap: 0.5rem;
  --tidbits-icon-color: #808080;
  --tidbits-icon-size: 20px;
  --tidbits-accordion-speed: 0.3s;
}
```

`:where(.tidbits)` keeps these at zero specificity, so any real rule (theme,
Global Styles, per-block inline `style=""`) overrides them without a fight.
